# 矮人要塞中文化：技術分析與路線

調查日期 2026-10-14；遊戲 Dwarf Fortress Steam 53.16（buildid 24557528）、DFHack 53.16-r2。對照的既有方案：DFI18n 0.2.4、維基翻譯組簡中資料 0.0.15、dfzh、dfint。

## 結論

1. **中文一定要靠原生程式顯示。** DF 的介面文字畫在 CP437 點陣字上（256 格），raws 改名或換字型圖都放不進幾千個漢字。可行的做法是在遊戲畫字時攔下英文、換成中文字圖。
2. **DFHack 是唯一的載入管道。** DF 不從 MOD 載入原生程式；DFHack 會執行每個已安裝 MOD 的 `scripts_modinstalled/`，Lua 再以 `package.loadlib` 載入 DLL。玩家只要從 Steam 裝 DFHack（免費）、訂閱工作坊項目，不必手動複製檔案。
3. **本專案自寫引擎，不依賴其他翻譯 MOD。** 一個工作坊項目同時帶繁中、簡中兩種語言的字典與字型（共用一份引擎），遊戲中隨時切換；還沒選過語言時照 Steam 或 Windows 的語言判斷（第 24 點）。
4. **中文字交給遊戲自己畫。** 字典命中時讓遊戲畫等寬空白，再把那些格子的貼圖換成中文字圖；顏色、圖層、裁切都沿用遊戲的繪圖流程，不會先閃英文。
5. **現有簡中確實不全。** 以字面比對估算，exe 內大寫開頭的獨立 UI 句子約 21% 有譯文，raws 名稱約 71%；事件提示、人物特性與需求、程序生成敘述多半還是英文。

DFI18n 0.2.4 在 53.16 的缺口（研究時的觀察，也是本專案自寫引擎的理由之一）：DFHack 文字 hook 失效（`paintString` 在 DFHack 53.15-r3 移到 `dfhack.dll`）；新的組字路徑沒接；中文字佔 1.5 格，譯文超出原文寬度會被截斷（實測 `Quit`→「結束遊戲」只剩「結束」）；要等遊戲下一次重畫才換成譯文，開視窗時先閃英文；公開原始碼停在 0.2.2。

hook 內的流程：

1. 以整句英文（CP437 位元組）查字典：先查目前畫面的依畫面譯文（Lua 每幀把 DFHack 焦點字串傳給引擎，DFHack 的視窗開著時也加上底下遊戲畫面的焦點；限定了列的條目還要畫在那一列），再查整句字典，再依序比對句型規則（句型照開頭固定字的前 4 個位元組、沒有開頭固定字的照結尾分組，只比可能對得上的幾組，順序不變；結果與「沒中」都存進快取，下一幀直接用；「沒中」與還夾著英文的結果記下當時名稱表的版本，之後登記了新的世界生成名稱就重算），最後試被截短的字串（第 17 點）；都沒中就照原樣呼叫原函式。
2. 命中時，把譯文換成「每個中文字兩個空白」的影子字串交給原函式畫，遊戲照常處理座標、顏色與裁切。句型填入片段後比原文寬就放棄，照畫英文。整句貼圖開著時，名字與靠左的句型結果（「人名，職業」「Alåth Akgosîton，母雞，♀ (馴服)」）一字兩格算放不下的，改照字型實際字寬再比（`para_entry`），放得下就從原文起點緊排畫（遊戲畫字的 `translate_call`、DFHack 視窗的 `dfhack_place` 都收這種照字寬縮短的譯文）；比英文寬一點、壓到九成放得下的（`dict.rs` 的 `SQUEEZE`），替身字串照英文的格數，整句貼圖把那一行橫向壓窄畫進去（排版的長體）。置中、靠右的句型結果與一字兩格的字圖照舊照格數比。
3. 原函式返回後，在那些格子寫入中文字圖的 texpos，並設 `ADDCOLOR` 旗標讓字圖套用該格的前景色。分頁標籤這類往下位移半格的文字，遊戲在上下兩列各寫一次（上列標 `TOP_OF_TEXT`、下列標 `BOTTOM_OF_TEXT`，用字型表的半格字形）；這兩種格子改貼「往下位移半格」的字圖上下兩半，位置和英文相同。
4. 自動換行段落（`markup_text_boxst`，說明頁、教學、彈出視窗）：遊戲先把整段拆成單字，排版函式 `mtb_set_width` 算出每個單字的座標，再逐字畫出，畫字 hook 只看得到單字。所以另外 hook 排版函式：原函式排完英文後，把單字接回整段（換行與換色寫成遊戲的 `[R]`、`[B]`、`[P]`、`[C:前景:背景:亮度]` 標記，顏色寫成調色盤編號）查字典；有譯文就依中文規則重新換行（標點不放行首、英數詞不拆），替每個單字訂畫字計畫：每段中文交給同一列第一個英文單字（載體）畫，畫在載體座標加上位移的位置，其他單字不畫。捲動的清單裡遊戲依載體決定畫不畫，中文那列跟著一起出現或消失。
5. 遊戲的單字清單一律不改：彈出視窗排好的單字會存進存檔。早期做法把單字原地改寫成代號，實測要塞存檔 `world.sav` 解壓後有 11 個代號（抵達要塞的彈出視窗），讀檔或移除本 MOD 後會畫成亂碼。
6. 沒有譯文的段落照畫英文，遊戲一樣逐字畫：單字若剛好是字典裡的介面標籤（`All`、`Fish`）會被換成中文、夾在英文句子裡（實測編年史出現「The Paddles of 全」）。所以排版時也替這些單字登記「照畫英文」，畫字 hook 遇到就不查字典。段落釋放時沒有通知，位址可能被別的字串重用，所以座標也要和排版時相同才算。傳說頁照原文的段是譯文的一部分，跟著中文一起重新排版。
7. 錨定貼圖：出發準備畫面開了圖形時，分頁標籤（矮人、物品、動物…）不經畫字函式，遊戲把每個字元當成 1×2 格的錨定貼圖（`add_anchored_tile`，貼圖編號取自字型表 `small_font_texpos`／`large_font_texpos`）一格一格放。hook 依貼圖編號反查字元，把同一列連續的字元接成標籤，等下一個不相連的貼圖或畫字呼叫時查字典；命中就把那些格子的錨定貼圖換成中文字圖，置中。錨定貼圖照原尺寸從固定的上緣畫起，英文字型表的字（8×12）大寫字母約 10 px；一般大小的中文會壓到分頁下緣，所以標籤另用小一號（字身 0.75 格高）、靠上的字圖。
8. 自動換行的文字（工具列按鈕的提示框、訪客說明、人物頁概況的近期想法、冒險模式的宗教說明與日誌事件等）：遊戲用 `wrap_text` 把一段英文依寬度切成幾行（`vector<string*>`），再一行一行畫，整句比對只看得到片段。`wrap_text` 只是把一個字串包成一段再呼叫真正切行的 `wrap_lines`（輸入是接成一句的幾段字串），也有程式直接呼叫 `wrap_lines`，所以 hook `wrap_lines`：切好之後把輸入接回整句查字典，查不到就逐句查（見第 11 點），有譯文就依中文規則以同樣寬度重新換行，第 k 行中文交給第 k 行英文畫，多的英文行不畫；沒有譯文的行登記成「照畫英文」，畫到時把整句記進未翻譯紀錄（不記片段）。行字串可能被釋放後重用，計畫以位址登記、畫字時再比對內容。
9. 大部分提示框在遊戲啟動時的靜態初始化就切好了，早於本引擎載入，hook 攔不到。所以 `enable` 時掃描 .text 裡呼叫 `wrap_text` 的地方，找出三個參數都是常數的呼叫（`lea rcx,[rip+全域變數]`、`mov r8d,寬度`、前面剛組好的 `lea rdx,[rip+字串]`），讀出全域變數裡已切好的行，和原文的單字完全相同才補登記（53.16 有 575 句）。
10. 彩色文字框（人物頁的想法、記憶、性格、屬性）：遊戲把含換色標記的一整段交給 add_string，切成固定長度的行（`color_text_linest`：文字與每字顏色各 769 bytes），再逐行用 `addcoloredst` 畫。hook add_string：原函式切完後，去掉換色標記（每個字記下顏色）、在 `[P]`、`[R]`、`[B]` 處分段，逐段逐句查字典；全部都有譯文才依框寬重新換行，第 k 行中文交給第 k 行英文畫，譯文依原文位置上色（佔位的譯文用佔位原文的顏色，句型固定字用該句開頭的顏色）。缺一句就整段照畫英文，不拿行片段查字典，缺的句子記進未翻譯紀錄。
11. 逐句：遊戲拼段落時句間空兩格。整段查不到時在句末標點（`.` `!` `?` `"`）後的兩個以上空白處切句，每句各自查整句字典與句型。句型的佔位不能跨過這種句界，整段比對時才不會把下一句吞進佔位。整段用雙引號包住時（人物頁概況的引言），引號內一樣逐句查，引號換成字典 `""` 條目的譯文（「」、“”）。段落框還原句界時引號裡的不還原（石板刻文整段引在一句裡），但整段只有外框一對引號時（神明對天選者說的話）外框不算引號，裡面照樣還原。
12. 公告：遊戲把一則公告拼好存成報告（`world.status.reports`），左側警報清單用 `wrap_text` 畫（第 8、11 點），標 BOX 的種類另用段落框彈出（第 4 點）。段落框把單字接回時單字間只留一個空白、`[B]` 自成一字，和報告原文的空白不同：載入字典時替原文有連續空白或黏著 `[B]` 的條目與句型另登記這種寫法的別名，一條兩處都能用。
13. 查詞時大小寫不同也找得到：完全相同的寫法優先，再試全小寫，再試只差大小寫的條目（索引在載入時建好；只差大小寫的兩條譯文不同時不收）。公告常把介面上大寫的名稱寫成小寫（`the woodcutter`、`Trade Depot`）。
14. 戰報：遊戲把攻擊者、動詞、受擊者、部位、武器、傷勢一段段接成一句。句型分層寫（攻擊前綴只用在佔位裡，由傷勢外框接上），所有格 `{%1}'s {%2}` 也只用在佔位裡。攻擊者自己的部位（`with The woodcutter's right lower arm`）用可省略的佔位 `{~n}`，譯文不必重寫主人。部位名本身帶逗號（`first toe, right foot`）：片段以這種條目結尾、前面又不是清單的「, 」時，不套清單句型，整條當部位名。
15. 傳說模式的事件句：遊戲替每種歷史事件（`history_event_*st`，133 種）各有兩個描述函式，vtable +0xd0 拼完整句（「In 1, X settled in Y.」，日期由 FUN_140b92640 寫在句首），+0xd8 拼名詞短語（「the founding of X in 3」，日期在結尾），+0x110 是 XML 匯出不翻。句型來源寫在 `data/events`，由 `scripts/gen_events.py` 產生帶日期的整句與短語、依「誰的樣板比較通用」排序（見 translation-guide「傳說模式的事件句」）。很多事件在句號前接原因與情境（FUN_140b5a6c0，94 種原因、約 25 種情境）：字典裡 align 寫 `tail` 的片語另外存，查一段文字時句尾（短語則是結尾日期前）是這種片語就先去掉、其餘照常翻，再在句號前補「，片語」，最多兩段。句子以日期結尾（The artwork relates to … in 3.）時日期與片語屬於裡面的短語，這一層不去。
16. 有連結的段落（傳說頁）是一筆筆紀錄：整段查不到時一段（`[B]`／`[R]`／`[P]` 之間）一段翻，翻不出來的段照原文、整段記進未翻譯紀錄；一般段落（說明、彈出視窗）仍是缺一段就整段照英文。有換色標記的段（相關人物清單的 `[C:7:0:0](member)`）整段查。

23. 設定視窗裡「也翻成中文」的四個選項（預設值見 `lua/dflang.lua` 的 `OPTIONS`，改了立即生效，見第 24 點；`dflang.json` 的 `names`、`keys`、`music`、`partial`）。按鍵名、曲名、段落的選項是字典的執行期開關（`set_options`，查詢時才看），按鍵名與曲名的條目一律載入；名字音譯是音譯表的開關（`set_translit`），音譯表一律載入、組原名的函式一律掛上：
    - 原生語言的名字音譯：遊戲組原名的函式（FUN_140a94030，`native_name`，`(language_name*, string* out)`：first_name、綽號，再接該語言字表的原文字）和組英文名的 `translate_name` 用同一份字號，但名（first_name）只存字串、沒有字號可查字義，所以一律照拼法音譯（`translit.rs`）：子音（th、sh 等雙字母算一個）接母音是一節，母音後面不接母音的 n、ng 併進同一節，接不到母音的子音自成一節，每節查 `data/translit/translit.tsv` 換成一個字（新華社英語譯音表的寫法，繁中單獨的 sh 照台灣慣例用「希」）。名字的每個字以「·」相接，綽號照原文。hook 讓原函式照跑，把整個原名的音譯登記進名稱表（和英文名一樣，整句、佔位、傳說頁連結字都查得到），只有名的寫法也一起登記：傳說頁的事件句、相關人物清單的連結字只寫名（`Onsmost`），遊戲不經過組原名的函式。英文名開頭的原名同樣音譯，接字表組的中文時改用「·」（「洛蓋姆·刻槽靴」）。存檔清單的原名遊戲沒組過，句型改用 `{!n}`：名稱表沒有時照拼法音譯，音譯關著時照抄（像原名的照抄也算翻好，傳說頁戰爭連結「原名, "英文名"」才翻得出來）。四種語言 8,488 個原生字都切得出表上有的音節。音譯一個音節一個字，中文兩格算常比英文寬，靠第 2 點的照字寬再比放進去。間隔號在中文字型裡是全形，整句貼圖照半個字寬排（`atlas::narrow`，世界生成名稱的「·」也一樣）；一字兩格時是 CP437 的「·」，本來就只佔一格。

    - 配樂曲名：暫停選單的曲名寫在 `data/screens/*.Options.tsv`，align 寫 `music`；選項關著時照原文（全域字典會把曲名 `Dolomite` 翻成石材名），開著時用譯文。
    - 段落缺句時其餘照翻：拼成一整段的文字（人物頁的彩色文字框、自動換行的提示與公告、段落框、DFHack 的說明段落）有幾句翻不出來時，翻得出來的照翻、其餘照原文接在原位（一個字一片，彩色文字框照原文每個字的顏色上色），和前後的中文空一格；一句都翻不出來時照舊整段照英文。缺的句子照樣記進未翻譯紀錄。`{%n}` 不放寬：句型靠它判斷該套哪一條。

24. 設定改了立即生效（`lua/loader.lua` 的 `apply`，設定視窗與 `dflang` 指令改完 `dflang.json` 就呼叫）。只有改用其他翻譯 MOD（`dflang lang off`：DFCN 是遊戲啟動時由 dfhooks 載入的 DLL、DFI18n 的腳本只在啟動時執行）要重開。各項的做法：
    - 「也翻成中文」的選項與整句貼圖：只換開關，接著 `refresh` 讓已經算好的東西照新設定重算：字典的句型快取清掉；段落（mtb）、提示（lines）、彩色文字框（ctb）、DFHack 段落登記的畫字計畫都記著算的時候的設定版本與字典（`hooks::Stamp`），版本不同時，提示、彩色文字框、DFHack 段落在畫到那一行時照記下的整句原文重算同一句的每一行；沒有連結的段落在畫到它的單字時照現在的字典重訂（`mtb::word_plan`：遊戲只在寬度改變時才呼叫排版函式，彈出視窗開著時一直不會，原本換了語言那段就一直照英文）。有連結的段落（傳說頁）等遊戲下次呼叫排版函式時，先讓遊戲照英文重排一次再重訂（連結字的座標照中文搬過，`mtb::rewrite` 的 relayout），不然搬過的位置會再搬一次；重排前照舊計畫畫，換了語言（字圖編號對不上）或關掉整句貼圖（舊計畫的字要靠整句貼圖畫）時那段先照英文。
    - 字重、中文字型大小：`set_typeface` 換整句貼圖的字型與字身、重量段落用的字寬（`metrics.rs`）；整句貼圖的點陣與貼圖快取在主執行緒下一次畫字時丟掉（`overlay::restyle`）。換字重另外畫一張字圖集（`overlay off` 用），新貼圖的 texpos 寫進字典（`update_texpos`，字圖編號不變）。字圖集與字寬一律照遊戲啟動時的格子大小，和啟動時畫的一致。
    - 語言：包裡 `dflang/` 放共用的引擎、特徵碼與吉祥物，兩種語言的字典、名稱字表、音譯表、字圖集用字（`glyphs.txt`）與字型子集各放在 `dflang/zh-Hant/`、`dflang/zh-Hans/`。換語言時引擎改讀另一種語言的字典（`set_glyphs`／`load`…／`commit`，記在那個資料夾底下，切回來用 `use_dict` 直接換）、字圖集、字型、名稱字表與音譯表，字典指標整個換掉；吉祥物重畫名牌（`load_mascot`）。世界生成名稱存字的代號、原名存原文，查的時候才照目前語言的字表與名字音譯開關組中文（`names.rs`），不必等遊戲再組一次名字。
    - 換下來的字典、字型、字圖集照留不釋放（遊戲執行緒可能正在讀），每種語言、字重各一份、切回來重用：來回切換記憶體不會一直漲（實測 15 輪後多約 70 MB，主要是另一種語言的字典與另一種字重）。
    - 還沒選過語言（`dflang.json` 沒有 `lang`）時照系統判斷（引擎的 `system_lang`，`locale.rs`）：先看 Steam 用戶端的介面語言（`SteamAPI_ISteamUtils_GetSteamUILanguage`，tchinese／schinese；遊戲自己的語言沒有用，DF 在 Steam 只支援英文），不是中文再看 Windows 顯示語言清單裡第一個中文（`GetUserPreferredUILanguages`），再看地區格式（`GetUserDefaultLocaleName`）。zh-TW、zh-HK、zh-MO 與寫了 Hant 的是繁體，其他中文是簡體；都不是中文用繁體。系統字碼頁不看（開了 UTF-8 時是 65001）。Steam 的介面存取函式名稱帶版本號（53.16 附的 `steam_api64.dll` 是 `SteamAPI_SteamUtils_v010`），找不到就跳過 Steam。
    - 合併前（0.4.0 以前）一種語言一個包。舊玩家沒選過語言時沿用原本的語言（`keep_old_lang`）：舊版每次啟動都寫 `dfhack-config/dflang-atlas-<語言>.png`（沒有字重），取最後寫入的那張的語言記進 `dflang.json`，舊檔刪掉。原本的簡中項目（`cat_df_lang_zh_hans`）停在 0.4.0，它的載入器也叫 `dflang_zh_hans.lua`：本包放一份空的同名檔，DFHack 同名腳本只執行腳本路徑上的第一份，路徑照工作坊項目編號排，本項目（3820630135）在舊簡中項目（3820630318）前面，舊載入器就不會和本包同時啟動引擎、多註冊一組小工具。
    - 遊戲讀取中不能註冊新字圖：DFHack 在讀取 raws 或存檔時（`Textures.cpp` 的 `loading_state`，看 `new_region` 的 `raw_load_stage`、讀檔畫面的 `cur_step`）把新貼圖都放進保留範圍，保留範圍滿了就註冊失敗（handle 是 0）、畫好的貼圖也不釋放，而且依路徑記住失敗的結果。這個狀態只在那幾個畫面的 `logic` 裡更新：建立新世界的設定畫面 `raw_load_stage` 停在 0，退回標題畫面後常常還是讀取中，直到載入或建立世界（實測沒有存檔時第一次打開就是；有存檔時曾有第一次打開、退回後就能註冊的）。所以換語言、字重前先註冊一張 1×1 的貼圖試試（`textures_ready`）：落在保留範圍或失敗就先不換這兩項，其他設定照套，記下 `state.pending`，畫面切換、世界載入時再套用一次；試過之後才碰上讀取（註冊到一半拿到 0）時換回原本的設定，下次換檔名重畫。試的貼圖不刪：DFHack 53.16-r2 的 `dfhack.textures.deleteHandle` 實測會讓遊戲當掉。

已知限制：

- 字圖與吉祥物、工作指令按鈕圖共用 DFHack 的保留貼圖範圍（10,000 格，DFHack 自己用掉約 1,000；1080p 的吉祥物佔 168 格、按鈕圖 36 格）。每個中文字九張（一般的左右兩格、往下位移半格的上下列各兩格、錨定標籤用的小一號兩格、一格寬的窄字），三千多字約三萬兩千張，保留範圍放不下的落在 DFHack 的動態範圍；遊戲重載貼圖後動態範圍的 texpos 會變，載入器在畫面切換時看最後一張的 texpos，變了就整批重查。
- `overlay off` 時遊戲中途改解析度，字圖會被縮放，重開遊戲恢復清晰。整句貼圖照當下的格子大小畫，但段落的換行照啟動時量的字寬：之後字比格子寬時整行橫向壓窄，比格子窄時行尾多留一點空。
- `overlay off` 時一字兩格的字圖照英文的格子畫：遊戲照英文字寬一個個排的詞（選擇出發地點的金屬清單）中間空得很開，整句貼圖才接成一行（第 22 點）。
- 段落與提示框的譯文行數比英文多時，多的行掛在最後一行下方，可能畫到框外（提示框會蓋到下方的「快捷鍵：」）；段落高度會存進存檔，所以不改。譯文格數不超過原文時中文行數不會比英文多，`verify_mod.py` 檢查格數。
- 方框把框線畫在最後一列下緣時（冒險側欄、日誌的協議欄、冒險角色的名字框），最後一列中文的最下一像素仍會碰到框線；英文的下伸部（g、p、y）也一樣。整句貼圖認得出這種框時字往上挪一像素（第 22 點），和英文一樣貼近框線、不壓線。
- 字典一個英文只有一個譯名，名稱同字不同義時只能選一個：`pike` 取武器「長槍」，魚類 pike 也會顯示長槍；`ash` 取樹名「梣樹」，大寫的庫存材料 `Ash` 另寫整句「木灰」。介面標籤和名稱同字時靠整句條目擋住大小寫退回（`temp/inventory/fallback.tsv` 列出目前靠退回翻到的字串）。
- 名稱檔允許比英文多到 6 格；單獨畫出的短名稱（`ogre` 食人魔）整句貼圖開著時壓窄放進原文寬度，關著時多畫幾格、可能貼到右邊的文字。

- `dfhack.gui.showPopupAnnouncement` 的彈出視窗底下的「More」只在要塞畫面有中文（`data/screens/dwarfmode.tsv`）；冒險模式另寫在 `dungeonmode.tsv`。
- 彩色文字框、切行的提示框與 DFHack 的說明段落，每一段從英文那段的起始列畫：中文通常比較短（整句貼圖照字寬換行，又更短），段與段之間、框下方會留白（性格的特質段落、多行公告之間最明顯）。
- DFHack 的 `Label` 用 `NEWLINE` 把一句拆在幾個 token 裡、同一列又有好幾段字（換色的字、動態的數字）時，各段分開查，拆開後不成句的照英文（open-legends 的「這是一條不歸路.」的半形句點）。DFHack 視窗疊在別的 DFHack 視窗上時（launcher 開著時跑 open-legends），底下那個視窗的依畫面譯文照英文：焦點是最上層視窗的。`gui/settings-manager` 的 init 設定編輯器照英文：53.16-r2 的腳本在第 877 行就 `return`，那段程式不會執行。腳本若在包裝函式裝上前就把 `dfhack.screen.paintString` 存成區域變數，那個腳本的字照英文（包裝在引擎啟用時就裝，目前沒看到這種情況）。
- 整句貼圖：DFHack 視窗底部一列並排的幾個快捷鍵項目，各自從英文的起始欄畫，中文較短，項目之間的空隙比英文大。
- 整句貼圖：只有數字、沒有譯文的欄位對齊英文的結尾格，字型的數字比格子窄，同一欄的數字左緣會略不齊；冒險開局裝備與寵物頁右下的「剩餘裝備與寵物點數：160」沒有貼齊右緣（不在框裡，遊戲先畫一段較短的英文，把數字往左推）。
- 整句貼圖：英文剛好填滿按鈕（左右各剩一格）、畫面上又沒有同一欄的別項時，看不出是置中還是靠左，中文照置中：冒險角色每頁底下的「Accept …」只有一顆，技能頁的「Accept attributes and skills」填滿按鈕，中文置中，其他頁的字短、靠左；技能頁的「自訂」也只出現在那一頁，置中，英文是從左內距起排。
- 整句貼圖：DFHack 視窗外框（BannerPanel 的紅色 [ ]、Panel 邊框）照英文寬度，字變短時框內右邊留空（傳說主畫面的「[Ctrl+d: 同時匯出 DFHack 擴充傳說資料：開 ]」）。
- 介面縮放不是預設值時，標題畫面的吉祥物可能蓋到 Bay 12 標誌，可用 `gui/overlay` 移動。
- 記憶分頁在測試存檔（剛出發的要塞）沒有內容，只用離線樣本驗證；記憶與想法用同一個彩色文字框，畫法相同。
- 遊戲本身的英文有幾處錯字與多餘空白（`He  often greets…`、`stubborness`、`pomegranate wood wood`），句型照原樣比對，中文照字面意思翻（「石榴木木材」）。
- 改字典或引擎要重開遊戲；遊戲執行中 DLL 被鎖住，不能建置。
- 名字音譯（第 23 點）：音譯的名字常比英文寬（一字兩格時，單獨畫出的矮人名字約八成五放不下）。名字與靠左的句型結果放不下時：一字兩格的字圖（`overlay off`）改用窄字（一字一格的壓窄字圖，例「基布·科萊馬爾，礦工」）；整句貼圖照實際字寬比，壓到九成放得下就照九成，再放不下、但一字佔一格放得下（和窄字一樣密，約壓到七成三）也照原文格數壓窄（短的音譯名「伊德」放進「Id」兩格）。都從原文起點靠左畫，原本置中的名字也靠左；連一字一格都放不下才照英文。測試世界（2026-10-19）4.9 萬個歷史人物的原名與英文名、210 位居民的「名字，職業」，兩種畫法都沒有因為太寬照英文的。置中、靠右的句型結果照舊照一字兩格比：裝得進名字的只有出發／收復準備的標題（地區、據點名）、傳說畫面標題（世界名）、圖像編輯器標題（文明名），同一個世界的 612 個地區、1,990 個據點、26 個文明與世界名套進去都放得下。DFHack 用自己的程式組名字（`dfhack.translation.translateName`），不經過遊戲的函式：讀檔時預先登記的只有英文名與沒有語言的單字名（狗頭人），遊戲這次還沒組過的原名在 DFHack 視窗裡照原文。MOD 加的語言用了音譯表沒有的拼法（音節）時，那個名字照原文；名稱字表沒有的稱號（遺忘巨獸的「the Gill Sea of Waves」，測試世界 3 個）整個名字照英文。
- 按鍵名：沒有修飾鍵的 `Delete`、`Help`、`Slash` 這類字有一般譯名時照一般字典（介面按鈕優先）；鍵帽上印的名稱（Tab、Esc、Home、End、F 鍵，繁中的 Enter）照英文。
- 段落缺句時其餘照翻：遊戲啟動時就切好的提示框（第 9 點）若有句子照原文，那幾句不記進未翻譯紀錄（那時還沒畫到，記了會把沒看過的提示也記進去）。
- 拼音搜尋（設計表「拼音搜尋」）：輸入法打出的中文字遊戲的搜尋框收不到（遊戲逐位元組收 SDL 送來的 UTF-8，搜尋框變成亂碼），要用英文輸入狀態打拼音。清單項目要翻得出中文才比得到讀音：玩家取的名字、沒登記的名字照英文搜。上萬項的清單第一次打字只比得到當場翻好的部分（見設計表），兩三秒後再打一個字才完整。實機驗過庫存與傳說模式歷史人物清單（2026-10-20）；冒險模式的交談選單（比對英文關鍵字）、日誌與其他清單沒實機看過，不經 `std::string::find` 比對的清單打拼音不會有結果。

## 效能

DF 每一幀在模擬執行緒上跑 `render_things` 把字寫進畫面緩衝區，這段時間不模擬；主執行緒等它寫完才畫格子（`update_all`）。畫字 hook、句型比對都在 render_things 裡，整句貼圖在 update_all 裡。量法：`engine.overlay_dump()` 第一行是這三段每幀的耗時（`update_all`、其中整句貼圖的 `overlay`、`render_things`，微秒、指數平均）。`dflang off` 時其他 hook 都拆，只留 render_things 的 hook 計時；同一局開關交替量，差就是本 MOD 多花的時間。

DF 53.16，Ryzen 9 9950X3D，1080p，畫面上限 50 幀；210 位居民、三萬多件物品的要塞與 4.6 萬個歷史人物的傳說（2026-10-17）：

| 畫面 | 模擬執行緒每幀多花 | 主執行緒每幀多花 | 遊戲自己寫一幀 |
|---|---|---|---|
| 要塞主畫面 | 0～0.2 ms | 0.03 ms | 2.4～2.9 ms |
| 居民清單 | 0.2 ms | 0.06 ms | 5 ms |
| 庫存 | 0.4 ms | 0.17 ms | 2.8 ms |
| 人物頁性格 | 0.2 ms | 0 | 2.4 ms |
| 傳說歷史人物清單，持續捲動 | 0.8～0.9 ms | 0.5～1.6 ms | 0.7 ms |
| 快取全部清空的一幀（居民清單／人物頁性格） | 0.3 ms／4.4 ms | — | — |

- 模擬速度：同一個存檔讀進來後跑 40 秒，沒有本 MOD 49.2、50.7 幀，有本 MOD 48.7、50.8 幀，差在每次讀檔本身的起伏之內。畫面每秒 50 幀時，模擬執行緒每幀多 0.2 ms 約是模擬時間的 1%。
- 依畫面譯文用的焦點由 Lua 計時器每個模擬幀更新一次，約 45 µs（`dfhack.gui` 每呼叫一次約 40 µs，DFHack 視窗開著時多找一次底下的遊戲畫面）。
- 沒命中快取的一句（第一次出現、名稱表登記了新名字後重算的夾英文結果）比對句型約 0.03 ms；沒有句型索引時要掃過兩萬多條，約 0.35 ms，捲動傳說清單時每幀多花 5～8 ms。
- 整句貼圖捲動時的主執行緒成本是新的一行要點陣化成貼圖；主執行緒不擋模擬。
- 記憶體：讀檔後行程多約 110 MB（字典、字型、字圖）。模擬不設限、每 20 秒換一個畫面連跑一小時，句型快取 1.6 千筆（上限 5 萬）、整句貼圖的貼圖到上限 2,048 張後持平；行程每分鐘多 2～3 MB，翻譯開、關時一樣，是要塞自己的增長。

## 翻譯路線

全部文字靠靜態盤點取得，實機紀錄用來驗證與補漏。翻譯接近 100% 才上架工作坊；在那之前照新玩家的流程分輪翻譯（設定 → 建立世界 → 選出發地點 → 出發準備 → 要塞），每輪實機走一遍收集紀錄、依畫面分組翻譯、送審、實機截圖確認。

1. `uv run scripts/inventory.py` 把快照裡的 exe 字串與 raws 文字分類（介面標籤、句子、片段、單字、raws 名稱與描述、標記文字、程式字串），排出 `temp/inventory/todo.tsv`。53.16 扣掉程式字串與雜訊後約 42,700 條。翻好了沒有由引擎本身判斷（離線工具 `t` 的 `-s` 模式，繁簡都要翻得出來）：早期用 Python 仿寫的句型比對，清單句型在整句最外層也算命中，把 173 條含逗號的生物說明誤算成已翻。
2. 靜態清單分不出哪些字串會原樣畫上畫面：直接呼叫四個畫字函式的程式只有 123 個，從這些函式只追得回已知介面字串的一半；其餘是先存進資料結構再由共用程式畫出。沒被畫到的條目只是用不到，不會出錯，所以照優先序批次翻。
3. 遊戲執行時拼出的句子（名字、數字、隨機字詞＋片段）用句型規則翻；`dflang misses on` 的實機紀錄裡、整句不在靜態清單的字串會列進 `composed.tsv`。
4. MSVC 會把短字串編成指令裡的常數，字串表不一定有（標題選單的 `Settings`、`Mods` 就是）；這些靠實機紀錄補。
5. 繁簡逐句分開翻；規則在 `docs/translation-guide.md`，術語在 `glossary/`。維基翻譯組簡中資料（CC BY-NC 4.0）只當參考，`scripts/lookup.py` 在本機查閱，不收錄進本專案。字圖額度約 4,500 字；維基組簡中資料目前用了 2,437 個不同的漢字。

## 遊戲更新

1. `uv run scripts/make_patterns.py --check`：`engine/patterns.tsv` 的每個函式（引擎掛的 hook，即 `engine/src/hooks.rs` 的 `HOOKS`；只登記位址的 `wrap_text`；其他標過的函式）在新 exe 各恰好命中一次就不用改引擎；接著建置並實機看一次標題畫面。開局畫面的外觀與性格段落、冒險模式的訊息框、交談紀錄與通知清單、世界畫面的新聞另外寫死了資料的位移（第 18、20 點），改版後要實機看一次；重找位移時用 `uv run scripts/df_snapshot.py find`／`fn`／`callers` 查反編譯，再用開發腳本 `dflang-dev-fields`（`scripts/dev_lua/fields.lua`）對 DFHack 的欄位名：只看反編譯分不出欄位用途（世界畫面的 +0x8388 是派遣報告，新聞在 +0x8310）。世界生成名稱的字表用字的代號對，raws 改了字表要補 `data/names`；原生語言的字（raws 的 `language_*.txt`）改了拼法時，名字音譯表沒有的音節會讓那個名字照原文，要補 `data/translit`（第 23 點）；書名樣板取自 raws 的 `text_book_*.txt`，改了要補 `data/rules/titles.tsv`（第 21 點）；神造材料與神話物質的名稱由 raws 的 `vanilla_procedural/scripts/generators/divine.lua`、`materials.lua` 從固定字表組成，改了要補 `data/strings/names_divine_materials.tsv`。
2. 有失敗時跑 `uv run scripts/df_snapshot.py snapshot`；`VERSION.txt` 的 `warnings` 列出找不到的函式。
3. 找不到的函式：刪掉 `engine/patterns.tsv` 那一行再跑 snapshot，會改用已訂閱的 DFI18n `configs/functions.lua` 試著定位；仍找不到時跑 `decompile`，在 Ghidra 對照舊版反編譯（呼叫者、引用的字串）找到新位址，把函式開頭位元組手寫成特徵碼放回 `patterns.tsv`，`--check` 確認唯一後再跑 snapshot。
4. 函式都標到後 `uv run scripts/make_patterns.py` 重產特徵碼，`--check` 全過。
5. `uv run scripts/df_snapshot.py diff <舊版> <新版>` 列出新增的 exe 文字與 raws 文字，就是補翻清單。
